* 关于 edoc-tools
:PROPERTIES:
:CREATED:  [2021-12-29 Wed 18:34]
:ID:       5a884389-6aec-498a-90d5-f37168809b4f
:CUSTOM_ID: about-edoc-tools
:EXPORT_FILE_NAME: index
:END:
~edoc-tools~ 是 PDF 文件的查看器，可替代 DocView。区别在于页面不是由 ~ghostscript~ 之类工具预先渲染
再存到文件系统，而是按需渲染、保存在内存中。

渲染由名为 ~kc~ 的服务器程序完成。它读取 Emacs 发来的请求并返回结果，例如某一页的 PNG 图像。
文档类型由 ~kc~ 的后端决定：PDF 由 ~pdfcraft~ 渲染；Word 文档（~.docx~、~.doc~，以及 Flat OPC 或
WordML 2003 的 ~.xml~）由 ~WordCraft~ 在同一进程内排版并渲染；演示文稿（~.pptx~、~.pptm~、~.ppsx~、
~.potx~ 与 97-2003 的 ~.ppt~、~.pot~、~.pps~）由 ~DeckCraft~ 渲染。具体支持哪些类型以服务器自己报告
的为准：~kc doc-server list~，见[[#installing-the-kc-server][安装 kc 服务器]]。

* 安装 edoc-tools
:PROPERTIES:
:CREATED:  [2021-12-29 Wed 18:34]
:ID:       6ceea50c-cbaa-4d8a-b450-8067c5e8c9da
:CUSTOM_ID: installing-edoc-tools
:NEURON_DIRTREE_DISPLAY: false
:END:
通过 NonGNU ELPA、MELPA 或其他包管理器安装通常可以直接工作，不需要手工改动。只有在从源码安装，
或排查、调试问题时，才需要看下面的步骤。

~edoc-tools~ 需要一个 ~kc~ 服务器。服务器是独立二进制，以 ~kc doc-server run~ 方式调用；激活 Lisp 包时
不会自动编译它。安装 ~edoc-tools~ 和 ~kc~ 请按下面的顺序进行：

** 安装 kc 服务器
:PROPERTIES:
:CREATED:  [2021-12-29 Wed 18:34]
:ID:       e305cd0a-e798-4c2b-af27-21bcd936c1c9
:CUSTOM_ID: installing-the-kc-server
:END:
~kc~ 二进制取代了旧的 ~epdfinfo~ 服务器，行为一致。它由 knowcraft 项目构建，不随本仓库发布；
安装步骤见该项目的 README：https://github.com/yangyingchao/knowcraft 。

从源码构建：
#+begin_src sh
  $ git clone https://github.com/yangyingchao/knowcraft
  $ cd knowcraft
  $ cargo build --release -p knowcraft-cli
#+end_src
产物是 ~target/release/kc~。构建需要 Rust stable、C 工具链、~pkg-config~ 与 GLib 开发库；含 GUI 的
完整构建另外需要 GTK 4.12+、GtkSourceView 5、Poppler GLib、Fontconfig、GStreamer。

把 ~kc~ 放进 ~PATH~，或用 ~edoc-info-kc-program~ 指向它；Lisp 代码默认用 ~executable-find~ 查找。
edoc-tools 以 ~kc doc-server run~ 启动它，可选地把 stderr 追写到 ~edoc-info-kc-error-filename~。

~kc doc-server list~ 打印这个服务器能打开的文档类型，每行是 ~扩展名<TAB>后端~；~--json~ 输出对象数组，
~--jsonl~ 每行一个对象，字段为 ~extension~ 与 ~backend~（后端取值 ~pdf~、~word~、~slides~）。它不打开
数据库、不取写锁，可随时运行。

~kc~ 自身的问题请报到 knowcraft 仓库的 issue tracker；edoc-tools 的问题报到本仓库。

** 安装 edoc-tools 的 Lisp 代码
:PROPERTIES:
:CREATED:  [2021-12-29 Wed 18:34]
:ID:       32c4fc3b-b4ea-43bd-b92c-bdf2d3831fcf
:CUSTOM_ID: installing-edoc-tools-elisp-code
:END:
~edoc-tools~ 需要 ~tablist~ 包（1.0 或更高版本）才能正常工作，请确认装的是最新版 ~tablist~。包中声明的
其余依赖为 ~let-alist~ 1.0.4、~dash~ 2.18.0、~s~ 1.11.0，并要求 Emacs 26.3 或更高版本。

Lisp 代码在 ~lisp/~ 目录。把它加入 ~load-path~（或用包管理器安装该目录），然后激活 ~edoc-tools~：
#+begin_src elisp
  (add-to-list 'load-path "/path/to/edoc-tools/lisp")
  (edoc-tools-install)  ; 标准激活命令
  (edoc-loader-install) ; 按需加载，启动更快
#+end_src

~make bytecompile~ 只编译 Lisp 文件；~kc~ 服务器二进制由 ~PATH~ 提供，不由本目录树构建。用惯用的
包管理器安装 Lisp 代码（MELPA、NonGNU ELPA、~package-vc-install~、straight、elpaca 等）。

可以用下面的命令检查服务器是否找到并可用：
#+begin_src elisp
  M-x edoc-info-check-kc RET
#+end_src

安装完成后，先看 [[id:19a3daea-6fa6-4ac3-9201-d2034c46ad8c][查看功能帮助]] 和
[[id:8dccd685-18b8-4c98-977a-0fe2d66b724c][配置功能]] 两节。

+ 查看 :: 在缓冲区里查看 PDF 文档，键位与 DocView 类似。
  [[id:18d362e1-a1a3-4c51-9d45-04e2c53d8c0c][详见这里]]。
+ 增量搜索 :: 像普通缓冲区一样交互式搜索 PDF 文档，支持字符串，也支持 PCRE。
+ Occur :: 在一个或多个 PDF 文档中列出匹配某字符串或正则的行。
+ 跟随链接 :: 点击高亮链接，跳到同一文档的其他位置、外部文件、网站或其他 URI。也可以用键盘命令跟随。
+ 批注 :: 显示并列出文本批注与标记类批注（如下划线），编辑其内容与属性（如颜色），移动、删除或新建，
  并把改动写回 PDF 文件。[[id:5fff6471-a933-46d7-8ae9-b2fa4a9de952][详见这里]]。
+ 附件 :: 保存 PDF 中嵌入的文件，或用 dired 缓冲区列出它们。
+ 大纲 :: 用 ~imenu~ 或专用缓冲区（=M-x edoc-outline=）查看并浏览 PDF 的大纲。
+ SyncTeX :: 从页面上的位置直接跳到 TeX 源码，反向亦然。
+ 虚拟文档 :: 把一组文档当成一个大的 PDF 使用。
+ 其他 ::
  - 显示 PDF 的元数据。
  - 标记区域并把文本从 PDF 中 kill。
  - 用历史记录跟踪访问过的页。
  - 应用颜色滤镜，便于在暗光环境下阅读。

** 配置 edoc-tools 的功能
:PROPERTIES:
:CREATED:  [2021-12-29 Wed 13:51]
:ID:       8dccd685-18b8-4c98-977a-0fe2d66b724c
:CUSTOM_ID: configuring-edoc-tools-features
:END:
看完 ~edoc-tools~ 提供的功能之后，你可能想按需调整其行为。执行下面的命令可以完整配置各项功能：
#+begin_src elisp
  M-x edoc-tools-customize RET
#+end_src

~edoc-info-required-formats~ 列出 kc 必须提供的后端，默认只要求 ~pdf~；每次启动服务器时校验，缺哪个就
发一条 warning（不阻断），kc 版本过旧、不认识 ~doc-server list~ 时跳过校验；设为 ~nil~ 关闭校验。
~M-x edoc-info-list-supported-formats~ 在缓冲区里列出服务器报告的扩展名与后端，用来确认某项能力是否
可用。

** linum-mode

** display-line-numbers-mode
:PROPERTIES:
:CREATED:  [2022-01-03 Mon 08:31]
:ID:       f178ba41-0f5a-4d22-b4a8-889af1af566e
:CUSTOM_ID: display-line-numbers-mode

这个模式是 ~linum-mode~ 的替代品，Emacs 26 起可用。~edoc-tools~ 与它一起用效果不好，例如会让文档
里的横向浏览（~C-f~、~C-b~、~C-x <~、~C-x >~）无法进行。

** auto-revert
:PROPERTIES:
:CREATED:  [2021-12-29 Wed 18:34]
:ID:       24b671c6-c242-4983-9d11-38421d2752e9
:CUSTOM_ID: auto-revert
:END:
自动回退的做法是每隔 ~auto-revert-interval~ 秒轮询文件系统，也可以配合
[[https://www.gnu.org/software/emacs/manual/html_node/elisp/File-Notifications.html][文件通知]]
使用基于事件的方式。但这目前并不可靠，Emacs 可能在对应文件还在写入时（例如 LaTeX 正在编译）
就回退 PDF 缓冲区，导致报错。

使用较新的 [[https://www.gnu.org/software/auctex/][AUCTeX]] 时，可以在配置里加上下面这行，让 TeX 编译完成之后再回退 PDF 缓冲区。
#+BEGIN_SRC emacs-lisp
  (add-hook 'TeX-after-compilation-finished-functions #'TeX-revert-document-buffer)
#+END_SRC

** Tesseract OCR 过的 PDF 里文本选区不透明
:PROPERTIES:
:CREATED:  [2022-09-19 Mon 18:50]
:ID:       C3A4A7C0-6BBB-4923-AD39-3707C8482A76
:CUSTOM_ID: text-selection-is-not-transparent-in-pdfs-ocred-with-tesseract
:END:

这类 PDF 中选中的文字会被选区遮住，参见上游 pdf-tools 仓库的
[[https://github.com/vedang/pdf-tools/issues/149][这个 issue]]，里面有详细的绕过办法。下面的函数依赖
[[https://github.com/orgtre/qpdf.el][qpdf.el]] 包，可以把这类 PDF 转成文本选区透明的文件：
#+begin_src elisp
  (defun my-fix-pdf-selection ()
    "Replace pdf with one where selection shows transparently."
    (interactive)
    (unless (equal (file-name-extension (buffer-file-name)) "pdf")
      (error "Buffer should visit a pdf file."))
    (unless (equal major-mode 'edoc-view-mode)
      (edoc-view-mode))
    ;; save file in QDF-mode
    (qpdf-run (list
               (concat "--infile="
                       (buffer-file-name))
               "--qdf --object-streams=disable"
               "--replace-input"))
    ;; do replacements
    (text-mode)
    (read-only-mode -1)
    (while (re-search-forward "3 Tr" nil t)
      (replace-match "7 Tr" nil nil))
    (save-buffer)
    (edoc-view-mode))
#+end_src
注意这个函数会覆盖运行它的缓冲区所访问的 PDF 文件。要避免覆盖，把 ~--replace-input~ 换成
~(concat "--outfile=" (file-truename (read-file-name "Outfile: ")))~。
